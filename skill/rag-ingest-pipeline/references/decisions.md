# 设计决策记录（decisions）

改默认参数前先读对应节——每条决策都有实测数据背书，新语料偏离前提时才需要动。

## 1. 解析器选型：MinerU VLM standard 档（实测对比 2026-10）

| 方案 | 实测表现 | 结论 |
|------|----------|------|
| **MinerU standard（2.5-Pro 1.2B VLM, CPU）** | 乱码 0、空格正确、内容最全 | **默认**。VLM 直接读页面像素，字体映射问题不存在 |
| MinerU flash（轻量管线） | 设计字体→控制符/异体字/拉间距碎片 | 仅快速预览 |
| Docling（IBM, MIT） | 表格好(TableFormer)、无异体字，但内容比 VLM 少 ~1/3，图片占位符多 | 备胎；docx/pptx 入口用它 |
| Unstructured | 未实测——与 Docling 同类，中文 OCR 生态弱于前两者，换它=纯损耗 | 不用 |
| RAGFlow/MaxKB/Dify | 整平台，需 ES+MySQL+MinIO | 8GB 内存机器扛不住，且替代自建学习目标 |

**何时换**：语料以 docx/pptx 为主 → Docling；语料万页级+有 GPU → MinerU VLM sglang 引擎。

## 2. 切片参数：500 字 / 重叠 80 / 标题切分 + 父标题压入

- **按 Markdown 标题切**：一个产品/一个 SKU 基本完整落在一块，信息不拦腰截断
- **中位块长 ~720 字符**（实测）：500-800 是常见 chunk 预算的甜区，规格表不会被二切
- **父标题压入子块**：`### 规格参数` 块本身不含产品名，压入后"某产品 净含量"才能命中
- **何时调**：评测集 Hit@3 < 90% 且抽查发现答案块被切断 → 加大 chunk_size；块内噪音多 → 减小

## 3. 去重边界：只删一字不差，保留功能性冗余

- 删：切片重叠产生的复制块（"来源+内容"哈希）。实测 168 条只删 1 条
- 留：索引行 vs 详情段（多粒度，答不同问题）；SKU 记录重复的卖点文案（自含性）
- **禁止语义去重**：会把刻意保留的多粒度内容误判删除。重复的真正防线是"单一来源纪律"（同一内容只允许一个源入库），不是下游算法
- 上万条+多源汇入时才考虑 MinHash

## 4. 查询通道：三条路，按查询类型路由

| 查询类型 | 通道 | 原因 |
|----------|------|------|
| 语义类（"XX精油的功效"） | 向量 + 重排 | 语义理解是向量强项 |
| 精确值类（编码/型号/单号） | metadata where 过滤 | 向量对长数字串天然弱（xfail 实证） |
| 全局概览类（"有哪些产品"） | 索引块（入库时保留索引 md） | 索引块就是为这类问题生的 |

## 5. 重排：bge-reranker-base 起步，量化驱动升级

实测（11 条评测集）：Hit@1 81%→90%，Hit@3 90%→90%。语料小而净时收益有限，语料脏/大收益放大。内存富余换 bge-reranker-v2-m3（多语言更强）。**换模型后必须重跑 eval 对比**，无收益就退回。

## 6. 存储：ChromaDB 本地文件夹起步

- <10 万块：Chroma PersistentClient（零运维、随拷随走）
- 服务化/多并发：pgvector（业务库同表存向量，运维最简）或 Qdrant（自带后台）
- 千万级分布式：Milvus（大厂场景，本项目用不到）

## 7. 评测方法论

- 黄金问题集 = 10-15 条，覆盖：口语化语义查询、精确值查询、全局概览、**1-2 条 xfail**（文档化已知限制，防止"修复"幻觉）
- 指标 = Hit@3（可交付线 90%）+ Hit@1（排序质量，重排器主战场）
- 改任何参数 → 必跑 eval 对比，数字不涨就不合入
- expect 关键词选择原则：必须是**答案块里必然出现**的词（产品名/型号/独特短语），不要用泛化词（"功效""介绍"）

## 8. schema 映射（数字原生 JSON→md）的唯一不可通用环节

每家公司的 JSON/数据库结构不同，这步必须写一次性小脚本（几十行）。铁律：
- 每个记录单元输出一个 `##` 段落，检索关键词前置（身份行：分类｜品牌｜型号｜价格）
- 与规格表重复的压平文本（"参数信息 品牌 X 型号 Y…"）要剥离，同一内容进两份向量稀释检索密度
- 图片路径只留 3 张示例+总数（几百条路径会撑爆 chunk）
- 空字段直接丢弃，不输出"无"
- 产出后跑 `review` 人工抽查再入库
